## 全体の仕組み

```

          ▼
       server.js（127.0.0.1:3939）
          ├─ 音声認識サーバー stt/stt_server.py（127.0.0.1:3941）… ReazonSpeech / Whisper + Silero VAD
```

## 名前・性格・ルールを変える（AI の設定）

画面右の「設定」の **「名前・性格」** で、次のものを変えられます（AivisSpeech モードのとき。ElevenLabs モードは ElevenLabs の管理画面で設定します）。「保存して反映」を押すと、AI が返事をしていなければすぐ反映します（それまでの会話の続きは忘れます）。設定は `data/persona.json` に保存され、iPad などから話しかけても同じ AI になります。変えられるのは PC の画面からだけです（iPad などでは見るだけ）。

| 項目 | 内容 |
|---|---|
| AI の名前 | 会話ログ・字幕・人格のプロンプトに使います（初期値は `.env` の `AI_NAME`、なければ「あまね」）。呼びかけで反応させたいときは、設定の「呼びかけの言葉」にも足してください |
| あなたの呼び方 | AI からの呼ばれ方（初期値は `.env` の `USER_NAME`、なければ「ご主人様」） |
| 話し方・性格 | 丁寧語かタメ口か、どんな雰囲気で話すか。「話し方のひな形」（執事・親しい友だち・元気なアシスタント・やさしい先生）から選んで、書き換えることもできます |
| 返事の長さ | 短め（1〜3 文）・ふつう（2〜4 文）・詳しめ。長くすると、話し終えるまでが長くなります |
| キャラクター設定 | 生い立ち・口ぐせ・好きなものなど |
| 守ってほしいルール | 1 行に 1 つ。安全に関わる決まり（作業の前の確認など）とぶつかるときは、安全のほうを優先します |
| あなたについて | 住んでいる地域・家族・好みなど。天気や道順で場所を言わなかったときは、ここの地域を使います |

- 名前と呼び方は 20 文字、話し方は 400 文字（1 行にまとめます）、ほかは 1000 文字までです。
- 作業担当が動いている間（終わってから 2 分まで）は保存できません。少し待ってから保存してください。
- 書いた内容は、会話のたびに頭（Claude Code）に渡ります（Anthropic に送られます）。人に知られたくないことは書かないでください。
- **呼びかけの言葉**: 画面の設定で変えます。造語でも、読み仮名が合えば反応します（例: 「あまね」は「天音」と認識されても反応します）。周りの会話に反応しないよう、話し始め（「ねえ」「やあ」などの後ろ）の呼びかけだけに反応し、「あまねく」「あまねって」のように後ろに言葉や助詞が続くときは反応しません（判定は `lib/wake.js`）。
  - 呼びかけの言葉を選ぶときは、ふだんの会話やテレビに出てこない、3〜4 音の言葉が向いています。「あまね」は、合成音声で試したとき、雑音の中でも 4 回に 3 回ほど聞き取れました。
- **人格のプロンプトそのもの**: `prompts/local-brain-system-prompt.md` を編集します（`{{AI_NAME}}` `{{USER_NAME}}` `{{STYLE}}` `{{LENGTH}}` は設定の「名前・性格」の値に置き換わります。キャラクター・ルール・あなたについては後ろに付きます。処理は `lib/persona.js`）。

## 音声認識

| `STT_ENGINE` | 特徴 |
|---|---|
| `reazonspeech`（初期値） | 日本語専用の k2 モデルを CPU で実行。短い発話なら数百 ms |
| `whisper` | kotoba-whisper を GPU で実行。精度は高いが、短い発話でも 1 回あたり一定時間かかる |

- 声かどうかの判定（Silero VAD）で、物音を文字にしないようにしています。`STT_MIN_SPEECH` で感度を調整できます。
- 画面の設定の「マイクの感度」を下げると、周りの騒がしさより大きな声だけを発話として扱います（口元のマイクと組み合わせると、周りの話し声を拾いにくくなります）。
- 待受中は、テレビやドライヤーのように鳴り続ける音があっても、その大きさに数秒で慣れて声を区切ります（`public/mic-vad.js` の `adaptive`）。区切りが来なくても最長 6 秒ごとに切って呼びかけを調べ、長いかたまりは音声認識サーバーが声の切れ目（Silero VAD）で区切り直して、区切りごとに話し始めの呼びかけを探します（ReazonSpeech のとき）。会話中は、長く話し続けたときに声を雑音と覚えないよう、この慣れ方は使いません。
- テレビの声に重ねて呼びかけると、聞き取れないことがあります。テレビの声が途切れたときに呼ぶか、テレビの音量を下げてください。
- 呼びかけの言葉と、画面の設定の「認識ヒント」に書いたひらがな・カタカナ・漢字の言葉は、認識されやすくなります。
- ReazonSpeech は「？」などの記号を出さないので、会話中の発言が疑問文なら「？」を付けます（`stt/question.py`）。「〜ですか」「〜かな」などのはっきりした疑問の終わり方や「何・どこ・いつ」などの疑問詞を含む文の形と、話し終わりの声の上がり調子（「明日晴れる？」）で見分けます。普通の文に付けないことを優先しているので、見逃すこともあります（とても低い声や、語尾がかすれる声では上がり調子を見分けにくい）。言いかけ（「明日どこに」）や、長くて途中で区切った発言には付けません。
- テレビや家族の声に返事をしてしまうときは、設定の「会話中は、呼びかけた人の声だけを聞く」をオンにします（下の「呼びかけた人の声だけを聞く」）。
- 音声認識サーバーは `start.bat` が一緒に起動します。別に動かしたい場合は `.env` を `STT_AUTOSTART=0` にして `start-stt.bat` を使います。

## ElevenLabs モード

1. https://elevenlabs.io でエージェントを作ります。
2. `prompts/elevenlabs-agent-prompt.md` のとおりに、First message・System prompt・言語（Japanese）・声を設定します。
3. Client tool を 5 つ登録し（`run_task` / `get_task_status` / `get_current_datetime` / `show_content` / `hide_content`）、System tools の **End call** をオンにします。
4. エージェントを **公開（Publish）** します。
5. 画面の設定で Agent ID を保存し、声のエンジンを「ElevenLabs」にします。

エージェントを非公開にする場合や、使用量を表示したい場合は、`.env` に `ELEVENLABS_API_KEY` を設定します。API キーの権限は次のとおりです。

- ElevenLabs Agents: **書き込み**（署名付き URL の発行に必要）
- User: 読み取り（使用量の表示に必要）

## 作業の委任

- 依頼は、作業の重さによって `LIGHT_ENGINE`（初期値: Codex の Fast モード）と `HEAVY_ENGINE`（初期値: Claude Code の Opus）に振り分けます。
- 振り分けは「Laya（起動していれば）→ AI の判断 → キーワードのルール」の順で決めます。Laya を使う場合は `python -m pip install laya` のあと `start-laya.bat` を起動します。
- 権限の初期値は、Codex が `workspace-write`（作業フォルダの中だけ書き込み可）、Claude Code が `acceptEdits`（ファイル編集のみ自動で許可）です。`.env` の `CODEX_SANDBOX` / `CLAUDE_PERMISSION_MODE` で変えられますが、[SECURITY.md](../SECURITY.md) の注意を読んでから変更してください。
- 同時に実行できる作業は 2 件、1 件あたり最大 15 分です（`MAX_PARALLEL_TASKS` / `TASK_TIMEOUT_SEC`）。
- 作業のログは `logs/tasks.jsonl` に保存されます。

## 表示だけモード

画面の「表示だけにする」を押すと、会話ログ・状態の文字・ボタンを隠して、AI の姿（粒子の群れ・光る多面体・背景の光の糸）だけを画面いっぱいに表示します（ブラウザも全画面表示になります）。リビングに置いた iPad 向けです。

- 画面をタップ（クリック）すると、右上に「表示を戻す」が 4 秒だけ出ます。キーボードでは <kbd>H</kbd> で切り替えます。
- 端末ごとに覚えているので、次に開いたときも表示だけモードで始まります。万一戻れなくなったときは、URL の最後に `?ambient=0` を付けて開くと解除できます。
- 資料の表示（`<show>`）はこのモードでも出ます。エラーは画面の下に短く出ます。

## 縦型の収録モード（ショート動画を撮る）

画面の「縦型で収録」を押すと、画面の中央に縦 9:16 の枠を出し、その中に AI の姿・資料のパネル・字幕を収めます（ブラウザも全画面表示になります）。この枠を画面収録すると、TikTok・Instagram のリール・YouTube のショートにそのまま使える映像になります。

- 字幕: 話しかけた言葉（聞き取り中の途中の言葉も）と、あまねがいま話している文を、大きく出します。
- 声のクレジット: 選んでいる声の名前を、枠の左上に小さく出します（例: `AivisSpeech: まお`、`VOICEVOX:四国めたん`）。声によって、動画で公開するときの表記や商用利用の条件が違うので、声のモデル・キャラクターの利用規約も確認してください。
- 字幕と資料のパネルは、SNS のボタンや説明文に隠れない場所（枠の上 8%・下 22%・右 13% を空ける）に置きます。下の空いているところには、SNS の説明文が重なります。
- 画面をタップ（クリック）すると、右上に「収録を終える」が 4 秒だけ出ます。キーボードでは <kbd>R</kbd> で切り替えます。端末ごとに覚えているので、戻れなくなったときは URL の最後に `?rec=0` を付けて開きます（`?rec=1` で収録モードで開きます）。
- 枠の大きさは画面の高さで決まります。Mac の Retina や 4K の画面なら、そのままショート動画の画質（縦 1920 ピクセル）で撮れます。フル HD の画面では少しぼやけるので、ブラウザを全画面にして撮ってください。

## 画面への資料表示

AivisSpeech モードでは、AI が返事の中に次のタグを書くと画面に表示されます（読み上げはされません）。

```
<show title="見出し" place="right">Markdown の本文</show>
<show title="見出し" src="workspace の中のファイル・画像や Web ページの URL"/>
<show title="曲名" src="https://www.youtube.com/watch?v=…"/>
<show title="東京駅の地図" src="map:東京駅"/>
<show title="東京駅からスカイツリーへ" src="route:東京駅|東京スカイツリー|電車"/>
<hide/>
```

- 表示できるもの:
  - `workspace`（と `.env` の `SHOW_DIRS`）の中のファイル（画像・PDF・動画（mp4 / webm）・テキスト・Markdown・HTML）
  - HTML（作業担当が作ったゲームや動くページ）: パネルの中で動かして遊べます。中央に大きく出し、キーボードもそのまま使えます（下の「HTML を動かすときの安全」）。
  - Web ページ: 埋め込みを許可している https のサイトはそのまま表示します。許可していないサイト（大手サイトの多く）と http のページは、代表画像・説明と、読みやすく整えた本文（Firefox のリーダー表示と同じ仕組み）で表示します。
  - YouTube（「〇〇の曲をかけて」）: パネルで再生します。閉じると止まります。iPad などでは、ブラウザの決まりで自動再生されず、再生ボタンのタップが必要なことがあります。
  - 地図（`map:場所の名前`）と道順（`route:出発地|目的地|手段`。手段は 徒歩・車・電車・自転車。省略すると車）
- 置き場所（`place`）: `right`・`left`・`center`（大きく）。省略すると、Web ページ・地図・PDF・HTML は中央、ほかは右に出します。AI の姿はパネルをよけて動きます（中央のときは後ろで小さくなります）。
- Web ページは PC のサーバーが取りに行きます。家の中の機器（ルーターの管理画面など）やこの PC には接続しません（接続する瞬間の IP アドレスで確かめ、転送先も毎回確かめます。IPv6 は、この PC と同じ家の範囲（/48）にも接続しません）。開けるのは 80 / 443 番のポートだけです。
- ほかのサイトの画像（代表画像や、AI が表示する画像の URL）は、サーバーを通して読みます（`/api/web/image`。SVG は読みません）。ほかのサイトの動画はリンクで表示します（画面の CSP で、画像・動画はこのサーバーのものだけにしています）。
- 埋め込んだページに自動再生・全画面を許すのは、YouTube と地図だけです。パネルの見出しは、ページが名乗る題名ではなくサイトの名前（ホスト名）にします。
- パネルの文字の大きさは、設定の「パネルの文字の大きさ」で変えられます（端末ごとに覚えます。離れた場所の iPad などで見るときは上げてください）。
- 開発者ツールのコンソールで `amane.show({ src: "sample.png", place: "left" })` / `amane.hide()` を実行して試せます。

### HTML を動かすときの安全

作業担当が作った HTML は、Web ページの内容などにだまされて書かれたものかもしれないので、この画面から切り離した枠の中で動かします。

- スクリプトは動きますが、この画面・保存した設定・Cookie には触れません（名前のないオリジンで動かします。iframe の `sandbox="allow-scripts"` と、サーバーが返す CSP の `sandbox allow-scripts` の両方で隔離しています）。
- 通信はできません（このサーバーの API にも、外のサイトにも。API はほかのサイトからの呼び出しとしても断ります）。フォームの送信・新しい窓・この画面の移動もできません。
- 枠は二重にしています。外側はこのサーバーのスクリプトのないページ（`/api/app-frame`）で、中の枠が外のサイトへ移動するのを止めます（移動して、打った文字などを外に送られないように）。
- 動かす HTML は、パネルの枠の中に読み込むときだけ渡します（ブラウザのタブで直接開くと断ります。この PC のアドレスで、本物らしく見える偽のページにさせないため）。
- パネルの見出しは、ファイル名と「作業担当が作ったページ」にします。設定の欄などに入力している途中は、ゲームに入力を向けません。
- 動かすのは作業フォルダの中の HTML だけです（`SHOW_DIRS` で足したフォルダの HTML は、これまでどおり文字で出します）。
- WebRTC（ビデオ通話などの仕組み）のように、ブラウザの決まり（CSP）では止められない通信の手段が残ります。枠の中のページに、パスワードなど大事なことは入力しないでください。
- 使えるのは、HTML ファイルの中に書かれたスクリプト・スタイルと、data: / blob: の画像・音・フォントだけです。そのため、作業担当には「1 つの HTML ファイルにまとめる」ように頼んでいます（外のサイトのライブラリやフォント、別のファイルは読み込めません）。
- Chrome・Edge では、枠の中のゲームが固まっても、あまね の画面は止まりません（別のプロセスで動きます）。iPad の Safari では、ゲームが固まると画面も一緒に止まることがあるので、そのときは iPad の画面を読み込み直してください。
- パネルを閉じると、ゲームも止まります。

## 声のエンジン（AivisSpeech と VOICEVOX）

声には [AivisSpeech](https://aivis-project.com/)（無料）を使います。VOICEVOX をもとにした音声合成で、VOICEVOX より自然で感情豊かに話します（下の「声に気持ちを込める」）。`.env` の `VOICEVOX_URL` が空か `http://127.0.0.1:10101` なら AivisSpeech です（設定の名前は VOICEVOX のときと同じです）。

- 画面の 設定 →「声」→「AivisSpeech の声」で声を選びます（AivisSpeech に入れた声が並びます）。
- `VOICEVOX_AUTOSTART=1` にすると、AivisSpeech のエンジンも一緒に起動します（見つからなければ `VOICEVOX_PATH` に `AivisSpeech-Engine\run.exe` の場所を書きます）。
- Windows では DirectML で GPU を使います。CPU 内蔵の GPU だけの PC では、GPU を使わないほうが速いことがあります（`VOICEVOX_GPU=0`）。
- AivisSpeech は GPU を使っても 1 文に 0.8 秒ほどかかります（VOICEVOX より自然な分）。そこで、呼ばれたときのあいさつや待ち時間のつなぎの言葉など、毎回同じ言葉は、待受を始めたときや声・速さを変えたときに先に合成して覚えておき、すぐ話し始められるようにしています（`lib/tts.js`）。

**VOICEVOX にする**: [VOICEVOX](https://voicevox.hiroshiba.jp/)（無料）も同じ使い方（API）なので、次のように切り替えられます。

1. VOICEVOX を入れて起動します。NVIDIA のグラフィックボードがある場合は、VOICEVOX の「設定」→「エンジン」で GPU モードにすると、声の生成が速くなります。
2. `.env` を `VOICEVOX_URL=http://127.0.0.1:50021` にして、`start.bat` で起動し直します。
3. 画面の 設定 →「声」→「VOICEVOX の声」で声を選びます。

- VOICEVOX のときは、声に気持ちを込める機能は使いません。動画などで公開するときは「VOICEVOX:四国めたん」のようなクレジット表記が必要です。
- AivisSpeech に戻すときは、`VOICEVOX_URL` を消すか `http://127.0.0.1:10101` にします。

### 声に気持ちを込める

AivisSpeech のときは、頭（Claude Code）が、気持ちが変わる文の頭に `[うれしい]` のような印を書きます。印は読み上げず、その文から声の調子を変えます（次の印まで続き、返事ごとに「ふつう」に戻ります）。止めたいときは、設定の「声に気持ちを込める」をオフにします（その画面だけの設定です。オフにしても AI は印を書きますが、印は読み上げず、声の調子も変えません）。
印は `[うれしい]` のほか、全角のかっこや漢字（`［嬉しい］` など）で書かれても読み取ります。気持ちの名前でないかっこ（読み仮名など）は、印とみなしません。

| 印 | 使う場面 | 声の変え方（まお の場合） |
|---|---|---|
| `[うれしい]` | 喜び・驚き・楽しさ | からかい・緩急を大きく・少し速く |
| `[からかう]` | 冗談・軽いからかい | からかい・緩急を少し大きく |
| `[やさしい]` | ねぎらい・励まし | あまあま・少しゆっくり |
| `[おちつく]` | 落ち着かせる・静かに伝える | おちつき・緩急を小さく・少しゆっくり |
| `[かなしい]` | 残念・同情 | せつなめ・緩急を小さく・ゆっくり |

- 声のモデルのスタイル（「からかい」「喜び」「Happy」など。名前はモデルごとに違います）から、気持ちに合うものを名前で探して使います。合うスタイルがない声でも、緩急と速さは変えます（`lib/moods.js`）。
- スタイルを切り替えたときは、スタイルの強さ（`intonationScale`）を 1.5 にします。AivisSpeech では、この値が「感情表現の強さ」で、強さ 1.0 のままではスタイルの違いがほとんど聞き分けられないためです（2 に近づけると声が崩れることがあります）。
- 声の高さは変えません（AivisSpeech では、高さを変えると音質が落ちるため）。
- 同じ声のモデルの中でスタイルを切り替えても、読み込み直しは起きないので、話し始めは遅くなりません。
- VOICEVOX では使いません（強さの意味が違い、緩急もないため）。

## 待ち時間（AivisSpeech モード）

- 返事を考えるのに時間がかかるときは、「少々お待ちください。」（3.5 秒後）、「調べてみますね。」（Web 検索を始めたとき）、「もう少しお待ちください。」（12 秒後）のように、つなぎの言葉を話します。本当の返事が始まったら話しません。
- 作業が終わって自分から報告するときは、「お待たせしました。」（失敗したときは「すみません、ご報告があります。」）で話し始めます。

## 呼びかけた人の声だけを聞く（声紋）

リビングのように、テレビや家族の話し声がある場所向けの機能です。設定の「会話中は、呼びかけた人の声だけを聞く」をオンにすると（ローカル音声認識のとき。画面・端末ごとの設定）、次のように動きます。

- 「あまね」と呼びかけた人の声の特徴（声紋）を覚え、その会話ではその人を「主」として、主の声だけを文字にします。テレビや家族の声、あまね自身の声の回り込みは聞き流します。
- 事前の登録はいりません。呼びかけが短いと最初は見分けがあまくなりますが、会話で主の声を聞くたびに学び足して、だんだん確実になります。
- 主の声は、呼びかけた発話の先頭（1.5 秒ほど）からとります。「今すぐ話す」で始めたときなど呼びかけがないときは、あまねが黙っている間に最初に話した人を主にします。
- あまねが話している途中で話しかけたとき、音量を下げて止まるのも主の声のときだけです（話し始めの 1 秒ほどで判定します）。
- テレビなどが鳴り続けていても待たされないよう、6 秒ごとに区切って聞き取ります（話の途中で区切られたときは、続きをつなげます）。
- 声紋は PC の中で調べます（モデルは約 28MB。最初に使うときに `models` フォルダにダウンロードします）。覚えた声は会話が終わると忘れます。
- 見分けがうまくいかないときは、`.env` の `STT_SPEAKER_THRESHOLD`（初期値 0.45）で調整します。黒いウィンドウの `[stt] 声紋` の行に、区間ごとの似ている度合いと、聞いた（✓）・聞き流した（✗）が出ます。

## 会話のテンポ（AivisSpeech モード）

- 言いかけ（「〜けど」「〜て」など）で区切れたら、1.1 秒だけ続きを待ちます。「じゃあ、スカイツリーは？」のように上がり調子で短く聞いたときは待ちません。
- 返事を考えている間に話し始めると、前の発言の続きとして言い直したことになります。
- AI が話している途中で話しかけると、いったん音量を下げ、本当に話しかけられていれば読み上げを止めます（自分の声の回り込みは無視します）。

## 返事の速さ（AivisSpeech モード）

設定の「返事までにかかった時間を会話ログに出す」をオンにすると、返事のたびに次のような行が出ます（`logs/timing.jsonl` には常に記録します）。

```
返事まで 3.4 秒（区切り 0.6 / 認識 0.4 / 頭 1.2 / 最初の文 0.4 / 声 0.9）
```

| 項目 | 意味 | この PC での目安 |
|---|---|---|
| 区切り | 黙ってから、話し終わりと判定するまで | 0.55 秒（固定） |
| 認識 | 音声認識（CPU） | 0.4 秒 |
| 続き待ち | 言いかけ（「〜けど」など）で、続きを待った時間 | 0〜1.1 秒 |
| 頭 | Claude Code が最初の文字を返すまで | haiku 0.7 秒 / sonnet 1.2 秒（0.8〜3.6 秒とばらつく） |
| 最初の文 | 最初の文（「。」まで）がそろうまで | 0.2〜0.7 秒 |
| 声 | 最初の文の合成（AivisSpeech） | 0.9 秒（長さによらず、1 回 0.7 秒ほどかかる） |

- 合計は、haiku で約 2.7 秒、sonnet で約 3.4 秒でした（この PC。AivisSpeech は GPU、音声認識は CPU）。Web 検索をすると 8 秒ほどかかります（その間は「調べてみますね」とつなぎます）。
- いちばん効くのは頭のモデルです（`.env` の `BRAIN_MODEL`）。haiku は速い代わりに、返事が簡単・ちぐはぐになることがあります。
- 頭の Claude Code は、止まっていると起動に 1〜4 秒かかります。待受中の画面は 5 分ごとにサーバーに知らせ、頭を起動したままにしてもらいます（`BRAIN_IDLE_MIN` 分だけ会話がなければ、会話の続きを忘れるために起動し直します）。

## iPad・スマホから使う（リビングに置く）

PC はそのままで、リビングの iPad などをマイク・スピーカー・画面として使えます。聞き取り・返事・声の合成は、これまでどおり PC が行います。家の Wi-Fi の中からだけ使えます。

### 準備（最初に一度だけ）

1. `.env` に `LAN_ACCESS=1` と書いて、`start.bat`（Mac は `start.command`）で起動し直します。黒いウィンドウに `iPad などから: https://192.168.x.x:3942` と表示されます。
   - Windows のファイアウォールの確認が出たら、「プライベート ネットワーク」にチェックを入れて「アクセスを許可」を押します。Mac で「受信接続を許可しますか？」と出たら「許可」を押します。
   - 家の Wi-Fi が「パブリック ネットワーク」になっていると接続できません。Windows の設定 →「ネットワークとインターネット」→ Wi-Fi のプロパティで「プライベート ネットワーク」にします。
2. iPad の Safari で、表示された `https://…:3942` を開きます。
   - 「この接続ではプライバシーが保護されません」と出たら、「詳細を表示」→「この Web サイトを閲覧」で進みます（証明書を入れる前の、この一回だけです）。
3. 開いたページの手順で、証明書を入れます。
   1. 「証明書をダウンロード」→「許可」
   2. 設定アプリ →「ダウンロード済みのプロファイル」を開き、「詳細」→ 証明書 の SHA-256 のフィンガープリントが、PC の画面（「設定」→「iPad・スマホ」）に出ているものと同じか確かめてから「インストール」（同じ Wi-Fi の別の機器に証明書をすり替えられていないかの確認です。違うときはインストールしないでください）
   3. 設定 →「一般」→「情報」→「証明書信頼設定」で「AI AMANE Local CA …」をオン
4. Safari でページを開き直します。PC の画面の「設定」→「iPad・スマホ」→「つなぐための番号を表示」で出た 6 桁の番号を iPad で入れて、「つなぐ」を押します。
5. いつもの画面が開きます。画面を一度タップしてから「待受をオン」を押し、マイクを許可します。

### リビングに置くときのコツ

- iPad は電源につなぎ、設定 →「画面表示と明るさ」→「自動ロック」を「なし」にします（待受中は画面が消えないようにしていますが、念のため）。Safari を出したままにしたいときは「アクセスガイド」（設定 →「アクセシビリティ」）が便利です。
- 声が小さいときは、iPad の画面の 設定 →「声の大きさ」を上げます（iPad は、マイクを使っている間スピーカーの音が小さくなるため、最初から 2 倍にしています。上げても音が割れないよう抑えています）。それでも足りなければ、iPad に外付けのスピーカーをつなぎます。
- Safari にマイクを毎回聞かれるときは、設定 →（「アプリ」→）「Safari」→「マイク」を「許可」にします。
- PC はスリープしないようにします（Windows の設定 →「システム」→「電源」）。ログインしたら自動で起動したいときは、`start.bat` のショートカットをスタートアップフォルダ（<kbd>Win</kbd>+<kbd>R</kbd> で `shell:startup`）に入れます。
- 証明書は、作ったときの PC の IP アドレス用です。IP アドレスが変わるとつながらなくなるので、ルーターの設定で PC の IP アドレスを固定しておくと安心です。変わってしまったときは、`data/lan` フォルダを消して起動し直し、証明書を入れ直します（黒いウィンドウにも案内が出ます）。`https://PC名.local:3942` で開ける場合もありますが、PC やネットワークの設定によってはつながりません。
- PC と iPad の両方で画面を開いていても、返事は話しかけた画面からだけ聞こえます。作業の完了の報告も、その作業を頼んだ画面だけで行います。ただし、頭（Claude Code）はひとつなので、会話の内容は PC と iPad で共通です。

### 仕組みと安全

- PC の画面（`http://localhost:3939`）はこれまでどおり PC の中だけで待ち受け、iPad 用に別の HTTPS のポート（`LAN_PORT`、初期値 3942）を開きます。iPad の Safari は、HTTPS でないとマイクを使わせてくれないためです。
- 証明書は、最初の起動時にこの PC 専用に作ります（`data/lan`）。署名に使った鍵はその場で捨てるので、iPad に入れた証明書を使って、ほかのサイトの偽の証明書を作られることはありません。有効期間は約 2 年で、切れたら作り直します（iPad への入れ直しが必要です）。
- 使えるのは、番号を入れてペアリングした端末だけです。番号は 5 分で切れ、5 回間違えると使えなくなります。PC の画面には、つないだ端末の名前と IP アドレスが出ます。心当たりのない端末があれば「すべて解除」で解除してください（開いている接続もその場で切ります）。
- 家の LAN（プライベートアドレス）以外からの接続は断ります。
- サーバーの終了と、ペアリングの管理は、PC の画面からだけできます。ペアリングした端末からは、PC の画面と同じように会話・作業の依頼・資料の表示ができます。

## 使用量

- ElevenLabs モードでは、今期のクレジット使用量と、会話ごとの秒数・クレジットを表示します（`logs/usage.jsonl` にも記録）。
- AivisSpeech モードでは、Claude の API に換算した参考値を表示します。

## 開発メモ

- サーバーの API は `X-Amane: 1` ヘッダーのない POST を拒否します（ほかの Web サイトからの悪用対策）。ブラウザ側は `public/amane-fetch.js` が自動で付けます。
- `start.bat` を二重に起動すると、新しいほうが古いほうを止めて入れ替わります。
- 音声認識サーバーは、`.env` の `STT_URL` のポートで待ち受けます。開発中に、使っているものとは別に動かすときは、`STT_URL` と `PORT` を変えて `node server.js` を起動します。
- テスト: `npm test`（サーバー・画面の部品）と `python -m unittest discover -s test -p "test_*.py"`（音声認識サーバー）。
- Mac では `start.command` で起動できます（Node のパッケージと、`.venv` への音声認識のパッケージのインストールも自動で行います）。Mac 版の VOICEVOX は GPU を使えないので CPU で合成します。
- Linux では `npm install` のあと `node server.js` で起動できます（音声認識には Python 3.10 以上と `pip install sherpa-onnx huggingface_hub numpy` が必要です）。
