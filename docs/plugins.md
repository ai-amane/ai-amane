# 追加機能（プラグイン）の作り方

AI あまね には、タイマーや家電の操作などの機能を、あとから足せます。`plugins` フォルダに、機能ごとのフォルダを入れるだけで使えるようになります。同梱の `plugins/timer`（タイマー・アラーム・リマインダー）が見本です。

## 仕組み

1. サーバーは起動するときに `plugins/<名前>/plugin.js` を読み込み、使い方を頭（Claude Code）のプロンプトの後ろに付けます（`logs/brain-system-prompt.md` で確かめられます）。
2. 頭は返事の中に次のようなタグを書きます。タグは読み上げられません。

   ```
   <act do="timer.set" seconds="180" label="カップ麺"/>
   ```

3. 画面（`public/local-voice.js`）がタグを見つけて、サーバーの `/api/plugins/act` に送ります。サーバーは引数をプラグインが決めた型で確かめてから、プラグインの動作を呼びます。
4. 「確認」の動作（結果を聞くもの）と、失敗したときは、結果を「［追加機能の結果］」として頭に送り、頭がそれを言葉にして話します。
5. 「画面で確認」の動作（`confirm`）は、すぐには実行しません。頼んだ画面に確認のボタンを出し、利用者が「実行する」を押したときだけ実行します。
6. プラグインからの知らせ（タイマーが鳴った、など）は、頼んだ画面（PC か iPad など）にだけ届き、音を鳴らして声で伝えます。
   - その画面が開いていなければ、開いている全部の画面に届けます（声で話すのは PC の画面だけで、ほかは音だけ）。
   - 画面が 1 つも開いていないとき（起動し直した直後など）は、10 分まで預かっておき、画面が開いたら届けます。
   - 自分から話しかけるのは待受がオンのときだけです。知らせで始めた会話は、30 秒黙っていると終わります。

## plugin.js の形

```js
module.exports = {
  id: "timer",                 // フォルダ名と同じ。英小文字・数字・ハイフン
  name: "タイマー",             // 頭への説明の見出し・起動時の表示
  description: "タイマー・アラーム・リマインダー",
  requires: [],                // 使う本体の仕組み（下の表）。この本体に無い仕組みを書いたプラグインは読み込まない
  prompt: "いつ使うか、引数の書き方の注意など（頭への説明。省略可。文字列か、文字列を返す関数）",
  actions: {
    set: {
      description: "タイマーをセットする",           // 頭への説明に出る
      usage: ['<act do="timer.set" seconds="180" label="カップ麺"/>'],   // 書き方の例（省略すると、params を全部並べた形を出す）
      kind: "command",                              // command: 実行するだけ（既定） / query: 結果を頭に話してもらう
      localOnly: false,                             // true（か true を返す関数）: PC の画面からだけ実行できる（iPad など LAN の端末からは断る）
      // enabled: () => true,                       // false（か false を返す関数）なら使えない。頭への説明にも出さない
      // confirm: (args) => "玄関の鍵を開けますか？",  // 画面のボタンで確かめてから実行する（下の「画面で確認する動作」）
      // confirmLabel: "鍵を開ける",                // 確認のカードの実行のボタンの文字（12 文字まで。省略すると「実行する」）
      // confirmVoice: "owner",                     // 声でも許可してよいか: any | owner（声紋がオンのときだけ。既定）| none（ボタンだけ）
      params: {
        seconds: { type: "number", min: 1, max: 86400, integer: true, optional: true, desc: "秒数" },
        label: { type: "string", max: 30, optional: true, desc: "名前" },
      },
      run: async (args, ctx) => ({ text: "3分のタイマーをセットしました。" }),
    },
  },
  start(ctx) { /* サーバーの起動時に 1 回（Promise を返してもよい） */ },
  stop() { /* サーバーの終了時 */ },
};
```

### 引数（params）

- `params` に書いた引数だけが `run` に渡ります。タグの属性はすべて文字列なので、`type` に合わせて直してから渡します。
  - `type`: `"number"`（`min`・`max` は必須。`integer`）、`"boolean"`（`true` / `false`）、`"string"`（`max`（既定 200 文字）・`enum`・`pattern`・`multiline`）
  - 決まりは読み込むときに確かめます。知らない `type`・範囲のない数・正しくない `pattern` があると、そのプラグインは使いません。
  - `pattern` は値の全体に当てます（先頭と末尾の印は付けなくてかまいません）。
  - 文字列からは、改行・制御文字と `［］<>` を取り除いてから渡します（頭への知らせのふりをさせないため）。改行が要るときは `multiline: true` にします。
  - `optional: true` でなければ、無いときは断ります。`desc` は頭への説明の中で、値の書き方として出ます。
  - 合わなければ「seconds は 86400 以下にしてください」のような理由で断り、頭がそのまま伝えます。

### 結果とエラー

- `run` は文字列か `{ text }` を返します。`query` の動作は、この文を頭が言葉にして話します。`command` の動作は会話ログに出るだけです（頭はタグを書いたときに、もう「セットしました」と話しています）。
- `run` で `new Error("理由")` を投げると、その message を理由として頭が伝えます（「タイマーが2つあります。どれを止めるか聞いてください」のように、次にどうするかまで書くと会話がつながります）。
- それ以外のエラー（書き間違いの TypeError や、ファイル・通信のエラーなど）の中身は頭に渡さず、黒いウィンドウにだけ出します。
- `run` は 15 秒で打ち切ります。打ち切ったときは「時間がかかりすぎたので、結果が分かりません」と伝え、`ctx.signal` を止めます（通信に `signal` を渡しておくと、打ち切ったときに通信も止まります）。
- 実行はすべて `logs/plugins.jsonl` に残ります（どの画面から、何を、どの引数で、結果はどうだったか）。

### 画面で確認する動作（confirm）

解錠・購入・送信のように、取り返しのつかない動作に使います。

- `confirm` に確認の文（か、引数を受け取って確認の文を返す関数）を書くと、本体は `run` を呼ばずに、頼んだ画面に確認のボタン（「やめる」「実行する」）を出します。
- 利用者が「実行する」を押すか、確認が出ている間に「お願い」と言ったときだけ、`run` を 1 回呼びます（`ctx.confirmed` が `true`）。頭のタグや ElevenLabs のツールからは実行できません。
  - 声の答え（「お願い」「はい」「やめて」など）は、頭を通さずに画面が直接受け取ります（だまされた頭が代わりに答えられないように）。
  - 声で決められるのは、確認が出てから 1.5 秒たってからです（前の確認に言った「お願い」が、新しい確認に当たらないように）。
  - `confirmVoice` を書かない動作（既定の `"owner"`）は、その会話で「呼びかけた人の声だけを聞く」（声紋）が効いているときだけ声で決められます（テレビや家族の「お願い」で動かさないため）。`"any"` ならだれの声でも、`"none"` ならボタンだけです。
- 確認は 60 秒で期限が切れます。頼んだ画面からしか押せません。1 つの画面に出せる確認は 1 枚だけで、「実行する」は出てから 1 秒たつまで押せません。「やめる」を押した動作は、その画面では 30 秒出し直せません。
- カードの見出し（「SwitchBot：鍵を開ける」のような、何を実行するか）は、本体がプラグインの `name` と動作の `description` から作ります。確認の文はその下に出ます。
- **確認の文には、頭が書いた引数をそのまま入れないでください。** 機器の名前など、プラグインが確かめた値から作ります（頭がだまされると、「いつもの安全な操作です」のような文で押させようとするため）。
- 作業担当（Codex / Claude Code）が動いている間と、終わってから 2 分の間は、確認の動作を断ります。
- 端末の印は自己申告で、認証ではありません。この PC で動くプログラム（だまされた作業担当を含む）と、ペアリングした端末は、ボタンを押したのと同じ要求を送れます。とくに重い動作は `localOnly` にし、作業担当の権限を広げないでください。
- `confirm` の関数で `new Error("理由")` を投げると、確認を出さずにその理由で断ります（使えないとき・どれか選べないときなど）。
- 頭への説明には「（画面で確認）」と出ます。頭は「画面のボタンで確かめてください」と言うようにしてあります。

### 本体の仕組み（requires）

| 名前 | 使えるもの |
|---|---|
| `confirm` | 画面で確認する動作 |
| `confirm-voice` | 確認を声で決めてよいかの `confirmVoice` |
| `prompt-function` | `prompt` を関数にする（頭への説明を書くたびに呼ぶ） |
| `async-start` | `start` が Promise を返す（終わるまで、動作は「準備中」で断る。失敗・30 秒の時間切れなら使わない） |
| `prompt-changed` | `ctx.promptChanged()`（下の表） |
| `enabled` | 動作ごとの `enabled` |
| `signal` | `run` の `ctx.signal`・`ctx.deadline` |

古い本体に入れたときに、黙って違う動きをしないよう、使うものは `requires` に書いてください。

## ctx（プラグインが使える部品）

| 部品 | 使い方 |
|---|---|
| `ctx.device` | `run` と `confirm` の中だけ。頼んだ画面（端末）の印。知らせを届けるときに `to` に渡す（届け先の目印で、認証ではありません） |
| `ctx.signal` / `ctx.deadline` | `run` の中だけ。打ち切ったときに止まる AbortSignal と、打ち切る時刻（ミリ秒） |
| `ctx.confirmed` | `run` の中だけ。画面のボタンで確かめて実行したときに `true` |
| `ctx.notify({ text, chime, to })` | 画面に知らせて、声で伝える。`chime`: `"alarm"`（3 回鳴らす）か `"notice"`。会話中でなければ、知らせの言葉で会話を始める（待受がオンのとき） |
| `ctx.setStatus(items)` | 画面の上の中央に出す状態。`[{ id, text, endsAt }]`（10 個まで。`endsAt`（ミリ秒の時刻）があれば残り時間を数える） |
| `ctx.promptChanged()` | 使い方（`prompt`）や使える動作（`enabled`）が変わったことを知らせる（機器の一覧を読み込んだときなど）。本体は、会話の切れ目（最後の発言から 45 秒たってから）に頭を起動し直して新しい説明を渡す（説明が変わっていなければ起動し直さない。起動し直すと会話の続きは忘れる）。start の途中で呼んでも、start が終わったときに 1 回だけ知らせる |
| `ctx.store.load(既定値)` / `ctx.store.save(値)` | `data/plugins/<id>.json` に JSON で保存する |
| `ctx.env(名前, 既定値)` | `.env` の値を読む |
| `ctx.log(...)` / `ctx.warn(...)` | 黒いウィンドウに `[plugin:<id>]` を付けて出す |

## 入れ方・止め方

- `plugins` フォルダに、プラグインのフォルダ（中に `plugin.js`）を入れて、`start.bat`（Mac は `start.command`）で起動し直します。
- 止めたいときは `.env` に `PLUGINS_OFF=timer` のように書きます（カンマ区切り）。
- 読み込めなかったプラグインは、黒いウィンドウに理由を出して飛ばします（ほかの機能はそのまま動きます）。
- `plugins` フォルダは、同梱のもの（`timer`）以外は Git の管理に入れません（`.gitignore`）。自分で入れたものや購入したものが、うっかり公開されないようにするためです。

## ElevenLabs モードで使う

ElevenLabs の管理画面で、エージェントに次の Client tool を登録し、プロンプトに使い方（`logs/brain-system-prompt.md` の「追加機能」の部分と同じ内容）を書きます。

- 名前: `plugin_action`
- 引数: `action`（文字列。例: `timer.set`）、`args`（文字列。JSON。例: `{"seconds": 180, "label": "カップ麺"}`）
- 戻り値（結果の文）を、そのままユーザーに伝えるようにします。画面で確認する動作のときは、確認のボタンを出したことが返ります。

ElevenLabs モードでは、会話していないときの知らせ（タイマーが鳴った、など）は音と会話ログだけです（会話中なら、ElevenLabs に伝えて話してもらいます）。

## 安全について

- プラグインは、このサーバーと同じ権限で動きます（ファイル・ネットワーク・`.env` の値を使えます）。**信頼できる人が作ったものだけを入れてください。** サンドボックスの中で動くわけではありません。
- API キーなどの秘密は `.env` に書き、名前を `KEY`・`TOKEN`・`SECRET`・`PASSWORD` などで終わる形にします（例: `SWITCHBOT_TOKEN`）。この形の名前は、作業担当（Codex / Claude Code）や常駐の頭の環境変数には渡しません（`lib/proc.js`）。
  - ただし作業担当は `.env` ファイルそのものを読めます（SECURITY.md）。使える範囲を絞れるトークンなら、絞ったものにしてください。
  - 範囲を絞れないトークン（SwitchBot のトークンなど、鍵も動かせるもの）を使うときは、作業担当の権限を広げないでください（`.env` の `CLAUDE_PERMISSION_MODE` と `CODEX_SANDBOX` は初期値のまま）。
- 声は聞き間違えます。頭は Web 検索の結果などにだまされることもあります。`prompt` に「実行する前に復唱して確認を取る」と書いても、だまされた頭や、テレビの「はい」は防げません。
  - **取り返しのつかない動作（解錠・購入・送信・削除など）は、`confirm`（画面で確認）にしてください。** それでも心配なものは入れないでください。
  - 家の中だけで使ってほしい動作は `localOnly: true` にします。
- 引数の型と範囲は、`params` で必ず決めてください。頭が書いた値は、Web 検索の結果などに含まれる悪意ある指示（プロンプトインジェクション）の影響を受けることがあります。

## テスト

`plugins/timer/timer-core.js` のように、時間の計算や外部との通信を `plugin.js` から分けると、`node --test` で確かめやすくなります（`test/timer-plugin.test.js`）。
